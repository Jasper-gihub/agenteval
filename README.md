# AgentEval（草稿）

**大多数 agent 评测结论是噪声。这个库的工作是把它算清楚。**

## 它想解决的具体问题

来自上一个项目 DataAgent 的真实经历：

我给自己的 agent 做了两次 A/B 实验：

| 对比 | 准确率差 | 配对 McNemar p | 结论 |
|---|---|---|---|
| flash v0.2.0 → v0.3.0 | −6.6 点 | 0.607 | 不显著 |
| flash v0.2.0 → v0.3.1 | +1.7 点 | 1.000 | 不显著 |
| flash → deepseek（同 prompt） | +6.7 点 | 0.481 | 不显著 |

三次实验、两次改版、一次换模型，**没有一次能得出统计上站得住的结论**。
而整个过程里最有用的两个数字，都不是准确率：

- **未收敛题数**：flash 12/60 vs deepseek 3/60
- **工具调用次数**：v0.2.0 338 次 vs v0.3.1 172 次（−49%）

也就是说：漏掉的那个指标，比大家都在报的那个指标更有区分度。

## 核心主张

1. **配对，不要比两个准确率。** 只有"一个对一个错"的不一致对提供信息；都对/都错对判断差异没有贡献。
2. **先算需要多少题，再开始跑。** 跑完再算 p 值是本末倒置——你连这个实验能不能得出结论都不知道就花了 1.15M token。
3. **报区间，不报点值。** `0.483` 是一个点，`[0.36, 0.61]` 才是信息。
4. **区分采样噪声和任务难度。** 同一题跑 3 次，方差里有多少是模型随机性、多少是题本身难，决定了该加题还是加采样。
5. **成本是主指标之一，不是附属信息。** 一个准确率高 5 点但贵 10 倍的配置，在帕累托前沿上可能直接出局。

## 模块

| 模块 | 作用 |
|---|---|
| `stats.py` | 配对检验（精确 McNemar）、Wilson 区间、**样本量规划**、配对 bootstrap、方差分解、帕累托前沿 |
| `dataset.py` | YAML 任务集：题目、难度分层、金标准（execution-based） |
| `runner.py` | 执行器：并发、限流、断点续跑、trace 落盘、成本记账 |
| `report.py` | Markdown/HTML 报告：2×2 表、难度分层、成本-质量散点 |
| `gate.py` | CI 门禁：回归超过阈值就 exit 1 |

## 与 DataAgent 的关系

DataAgent 是它的第一个被试对象，也是它的第一个真实用户。
`evals/compare.py`、`analyze_trace.py`、`recompute.py` 里的能力会被抽到这里，
但不再绑定 SQL agent——任何"输入任务、输出答案"的 agent 都该能用。

## 回放验证：拿 DataAgent 的 4 个真实配置试刀

`python examples/replay_dataagent.py` 的输出（摘要）：

**60 题的 95% 区间宽 0.245，而观察到的最大差异只有 0.067——区间比差异大 3.5 倍。**

| 对比 | 不一致对 (b/c) | 准确率差 | McNemar p | Holm 校正后 |
|---|---|---|---|---|
| flash v0.2.0 → v0.3.0 | 9/5 | −0.067 | 0.424 | 1.000 |
| flash v0.2.0 → v0.3.1 | 5/6 | +0.017 | 1.000 | 1.000 |
| flash v0.2.0 → deepseek | 7/11 | +0.067 | 0.481 | 1.000 |

三次对比、Holm 校正后**全部不显著**。

实测不一致率 23.9% 下的可检出下限：

| 题目数 | 能检出的最小准确率差 |
|---|---|
| 60 | **17.3%** |
| 200 | 9.6% |
| **416** | 6.8%（正好是 flash vs deepseek 的差距） |

> 60 题只能证明 17 个百分点以上的差异。而所有实验观察到的差异都在 7 个点以内。
> **这不是"实验做砸了"，是"实验规模从设计上就不可能得出结论"。**

唯一不需要统计检验就能下的结论来自帕累托前沿：**flash v0.2.0 被 v0.3.1 完全支配**
（更准 + 同样免费 + 工具调用少一半），这种"免费改进"不需要 p 值也值得采用。
